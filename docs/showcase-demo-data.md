# Complete Showcase Database and Feature Walkthrough

This guide creates and checks a deterministic, fictional database for the
Production Operations platform. It is intended only for local development,
portfolio demonstrations, screenshots, and controlled non-production UAT.

## Fastest setup

From the repository root:

```bash
export DEMO_SEED_PASSWORD="Choose-A-Local-Only-Password"
bash scripts/build_showcase_database.sh
```

The default output is `showcase-production-ops.sqlite3` and the default
operational date is Friday **04 September 2026**. The filename is ignored by
Git. The build applies every migration, flushes only that dedicated showcase
database, seeds it, and runs 23 coherence checks.

To choose another safe output file or operational date:

```bash
bash scripts/build_showcase_database.sh \
  /absolute/path/production-ops-showcase.sqlite3 \
  2026-09-04
```

To use it while running the API, export the same `DATABASE_URL`:

```bash
export DATABASE_URL="sqlite:////absolute/path/production-ops-showcase.sqlite3"
export DJANGO_DEBUG=true
python manage.py runserver
```

In another terminal, start the existing frontend:

```bash
cd frontend
npm install
npm run dev
```

Open `http://localhost:5173/`, use the chosen password, and set the operational
date to **2026-09-04**.

## Interaction checks that intentionally change the database

Use a copy of the showcase database for these checks, then rebuild it.

1. As Team Leader 1, create one Green update and one Red issue. Confirm the Red
   issue appears once in Manager → Team Leaders and Manager → Materials.
2. Attach a small `.txt`, `.jpg` or `.png` evidence file and download it from
   the authorised evidence endpoint.
3. Confirm a suggested break, record return, complete checks, and resume the
   line. Verify no step can be skipped and the 40 minutes are preserved.
4. Accept the pending handover as the incoming Team Leader and confirm actor and
   timestamp evidence.
5. As Support, acknowledge the assigned filler action once. A repeated request
   with the same idempotency key must not create a duplicate transition.
6. In the browser developer tools, set the network offline, submit a supported
   safe action, restore the network, and use **Sync now**. Confirm one mutation
   and an empty outbox.
7. Keep Manager and Team Leader sessions open together. Create an update and
   confirm the WebSocket notification appears; then disable live delivery and
   confirm manual refresh remains available.
8. As Manager, edit a plan block, downtime record or shift window only on the
   intended disposable copy; confirm all progress and downtime calculations
   refresh from the stored data.

## Automated proof

Run the deterministic verifier at any time:

```bash
python manage.py verify_demo_data --date 2026-09-04
```

It fails with a non-zero exit code if any showcase contract is missing. The
seed-specific regression suite is:

```bash
python -m pytest operations/test_seed_demo_data.py -q
```

For the full feature and responsive evidence gate, run the repository's normal
backend, frontend and Playwright CI commands described in the README and the
[Factory UAT Checklist](factory-uat-checklist.md).

## Reset rules

- `--reset` deletes and rebuilds only `DEMO-*` records.
- `--full-reset` deletes every record in the selected local database and
  requires the exact confirmation token.
- The showcase build script refuses an output filename that does not contain
  `showcase` and end in `.sqlite3`.
- Never point the showcase build script at staging or production.
- Never replace fictional values with real employee, customer, quality,
  traceability or production data.
